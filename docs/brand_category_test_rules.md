# 브랜드×카테고리 비중 검정 판정 룰

`analysis/signal_matrix.py`의 `brand_category_test()`가 따르는 룰과, 주간 파이프라인으로 데이터가 쌓일 때 **언제 어떤 셀을 다시 보는지**를 정하기 위한 룰이다. 코드의 파라미터 값이 바뀌면 이 룰도 업데이트되고, 리포트, 대시보드, README가 이 검정 결과를 인용할 때는 이 문서의 조건을 통과한 셀만 "통계 검증 패스"로 쓴다.

## 1. 무엇을 검정하는가

브랜드별 VoC의 **카테고리 구성 비율**이 나머지 4사(pooled others)와 다른지. 절대량이 아니라 비중이므로 한 카테고리의 과대는 다른 카테고리의 과소를 동반한다(compositional). 과대·과소 셀을 짝으로 읽는다.

## 2. 세그먼트

| 세그먼트 | 소스 | 작성자 | 용도 |
|---|---|---|---|
| `web_customer` | blog, cafearticle | customer | **상품·여정 카테고리의 주 결과** |
| `web_advisor` | blog, cafearticle | advisor | 공급자 측(설계사·비교 콘텐츠) 신호 — 고객 불만으로 읽지 않음 |
| `youtube` | youtube_comment | 전체(규칙상 customer) | 브랜드 캠페인·이벤트 카테고리의 주 결과 |
| `all_pooled` | 전체 | 전체 | 참고용. 소스 믹스(YouTube 채널 규모)가 결과를 지배하므로 발견에 인용하지 않는다 |

소스를 풀링한 검정은 브랜드 특성이 아니라 채널 규모를 측정한다. LOO(§6)는 이 교란을 잡지 못하므로 `all_pooled`에서 robust로 표시되어도 발견이 아니다.

## 3. 대칭 서브셋

blog·cafe 문서는 수집 쿼리가 5사 대칭인 것만 포함한다: `{브랜드} 후기` 5개 + 일반 쿼리 2개(`자동차보험 비교`, `실손보험 추천`). 타겟 브랜드에만 있는 상품 쿼리(자동차보험·실손보험·보험금 청구·다이렉트)는 제외한다. 비대칭 쿼리를 경쟁사에도 수집하면 제외 조건을 풀고 이 문서를 갱신한다.

브랜드는 수집 쿼리가 아니라 **제목에 언급된 브랜드**를 따른다(`brand_source='title'`, 원래 값은 `brand_query`). 제목에 브랜드가 둘 이상이거나 없으면 쿼리 브랜드를 유지한다.

## 4. 검정 절차와 임계값

| 단계 | 규칙 | 파라미터 |
|---|---|---|
| 카테고리 제외 | 세그먼트 내 문서 수 < 30인 카테고리는 검정에서 뺀다(기대도수 가정) | `min_col_n=30` |
| 셀 미검정 | 브랜드×카테고리 n < 5인 셀은 ratio·z·p를 비우고 `note='n<5'` | `min_cell_n=5` |
| omnibus | χ² 독립성 검정 | — |
| 셀 검정 | n ≥ 30: 2-proportion z(pooled) / n < 30: **Fisher exact** | `small_cell_n=30` |
| 다중검정 | Bonferroni α = 0.05 / (브랜드 수 × 검정 카테고리 수) | `alpha=0.05` |
| MDE | 셀마다 80% 검정력에서 검출 가능한 최소 비율(over/under) | `power=0.8` |
| LOO | 유의 셀은 others에서 경쟁사를 하나씩 빼고 재검정, 전부 유의해야 robust | — |
| 수축 비율 | 브랜드 비율을 others 비율 쪽으로 m=20건만큼 당긴 사후 평균과 95% Beta 구간 | `shrink_m=20` |

## 5. 결과 읽는 법

- **유의하지 않은 셀**은 "차이 없음"이 아니라 "`[mde_ratio_under, mde_ratio_over]` 범위 밖의 차이는 없음"이다. 범위가 넓으면(예: 0.3×–1.7×) 판단 보류.
- **유의하지만 관측 비율이 MDE 안쪽인 셀**은 검정력이 낮은 검정에서 걸린 것이라 효과가 과대추정됐을 가능성이 높다(출력의 "below MDE" 줄). 발견으로 쓰지 않는다.
- **n < 30 셀**은 표시용 비율로 `ratio_shrunk`와 구간을 쓴다. 수축은 표시를 정직하게 하는 것이지 유의성을 만들거나 없애지 않는다.
- 거울상: 한 브랜드가 한 카테고리에 극단적으로 쏠리면(현대해상 태아·어린이보험 76%) 나머지 브랜드가 전부 반대 방향으로 유의하게 나온다. 이런 셀은 LOO에서 `fragile: drops without <브랜드>`로 잡힌다.

## 6. "통계 검증 패스" 승격 조건 (전부 충족)

1. Bonferroni 유의
2. LOO robust (`robust=True`)
3. 브랜드×카테고리 n ≥ 30
4. 관측 비율이 MDE 바깥 (`ratio ≥ mde_ratio_over` 또는 `ratio ≤ mde_ratio_under`)
5. 세그먼트가 §2의 용도에 맞음 (`all_pooled` 불가)
6. 해당 셀 문서 20건 샘플 검수에서 카테고리·브랜드·작성자 라벨 오류가 발견되지 않음

1~2는 코드가 `signal_tag`로 판정하고, 3~6은 사람이 발견을 쓸 때 확인한다. 1·2만 통과한 셀은 "cluster 시그널"로 남긴다.

## 7. 주간 운영 — 데이터가 쌓일 때 다시 보는 규칙

주간 파이프라인이 돌면 셀의 n이 늘어나고, 같은 셀이 자동으로 `n<5 미검정 -> n<30 Fisher -> n≥30 z`로 넘어간다. 코드는 매주 그대로 다시 돌리면 되고, 사람이 보는 시점은 아래 트리거로 정한다.

| 트리거 | 확인 | 조치 |
|---|---|---|
| 타겟 브랜드 셀의 `n_brand`가 `n_needed_2x`에 도달 | 출력의 "Power watch" | 그 셀의 유의 여부를 처음으로 해석한다. 그 전까지는 "미확정" |
| `n_needed_1_5x` 도달 | 같은 줄 | 1.5× 수준의 차이까지 판정 가능. 발견 문구의 범위를 좁힌다 |
| 셀이 유의 ↔ 비유의로 전환 | `mart.weekly_snapshot` diff | 전환 셀 20건 샘플 검수 후 발견 재작성 |
| 새 카테고리가 `min_col_n`을 넘어 검정에 들어옴 | "Excluded from test" 줄 변화 | 그 카테고리의 라벨 품질 20건 검수 |
| 분기 1회 | — | MDE·LOO 표를 세그먼트별로 재검토, 규칙 버전 갱신 |

누적 속도는 첫 증분 실행(신규 1,304건, 전 소스) 기준으로 추정만 가능하고, 실측은 몇 주치 `weekly_snapshot`으로 확인한다. 2026-11-03 기준 `web_customer` 타겟 브랜드 n=131이며, 자동차보험 셀은 2× 검출에 약 220건, 1.5× 검출에 약 860건이 필요하다. 주간 누적만으로는 수십 주가 걸리므로, 타겟 브랜드 상품 쿼리를 경쟁사에도 대칭 수집하는 확장이 병행 경로다.
